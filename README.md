# plae-tljg.github.io

LKM's personal site — long-form writing on mathematics and AI systems.

Live (staging): <https://plae-tljg.github.io/>

Static site built with **Astro 7** and deployed to GitHub Pages. Chinese and
English are first-class paths (`/zh/…`, `/en/…`), articles can belong to ordered
series, and the Markdown pipeline supports KaTeX math, tables and highlighted code.

---

## Publishing an article

Articles are written in the private writing workspace (`~/Music/blogs`), not in
this repository. This repo only receives the publishable subset.

```bash
npm run content:status      # see every article and its status
npm run content:sync        # copy everything marked `ready` into the site
npm run content:sync -- --preview   # also pull in-progress drafts, badged as previews
npm run dev                 # look at it locally
git add -A && git commit -m "publish: …" && git push
```

The push to `main` triggers `.github/workflows/deploy.yml`, which builds the site
and publishes it to the `gh-pages` branch. Nothing else to run.

The convention the sync expects — file names, frontmatter fields, statuses,
series, images — is documented in [`docs/CONTENT_CONVENTION.md`](docs/CONTENT_CONVENTION.md).

### What sync guarantees

- It only **reads** the writing workspace; drafts there are never modified.
- Only articles whose `status` is in the publish list are copied (`ready` by default).
- An article with `confidentialityChecked: false` is refused.
- Synced files are generated: `npm run content:verify` (also run in CI) fails if a
  synced file was edited by hand, so the writing workspace stays the single source.
- Preview articles are excluded from RSS and the sitemap and carry `noindex`.

## Commands

| Command | What it does |
|---|---|
| `npm run dev` | Local dev server at <http://localhost:4321> |
| `npm run build` | Build to `dist/` |
| `npm run preview` | Serve the built output |
| `npm run content:status` | Inventory of the writing workspace |
| `npm run content:sync` | Copy publishable articles in (`--preview`, `--dry-run`, `--only <key>`) |
| `npm run content:new` | Scaffold a new article following the convention |
| `npm run content:verify` | Check the repo still matches the last sync |
| `./deploy-gh-pages.sh` | Manual deploy (the fallback for the Action) |

Scaffold a new article:

```bash
npm run content:new -- --key wake-the-ai-less --series ai-maintainable-systems --order 1 --both
```

## Where things live

```text
src/
  site.mjs              site title, taglines, locales, series registry, sync config
  content.config.ts     Zod schemas for posts / pages / notes
  content/
    posts/<lang>/       GENERATED by content:sync — do not edit by hand
    pages/<lang>/       hand-written pages (about)
    notes/<lang>/       earlier site-local posts
    .sync-manifest.json record of the last sync (hashes)
  layouts/              BaseLayout, ArticleLayout
  components/           Header, Footer, PostList, Toc
  pages/[lang]/         home, archive, tags, series, notes, about, rss.xml
  styles/global.css     typography, dark mode, tables, KaTeX, code
scripts/content.mjs     the writing-workspace ↔ site bridge
docs/CONTENT_CONVENTION.md
```

Routes: `/` (language landing) · `/{lang}/` · `/{lang}/posts/<slug>/` ·
`/{lang}/series/<id>/` · `/{lang}/series/<id>/read/` (whole series on one page) ·
`/{lang}/archive/` · `/{lang}/tags/<tag>/` · `/{lang}/notes/` · `/{lang}/about/` ·
`/{lang}/rss.xml`.

## Staging vs launch

While `SITE_STAGING` is not `false`, every page carries `noindex, nofollow` and
`robots.txt` disallows everything — the site is a private staging area, per the
launch gate in the writing workspace's `AGENTS.md`.

At launch:

1. Set `SITE_URL` to the real domain in `.github/workflows/deploy.yml` and in
   `src/site.mjs`.
2. Change `SITE_STAGING` to `'false'` in `.github/workflows/deploy.yml`.
3. Add a `CNAME` file to `public/` if the domain is custom.
4. Optionally switch the repository's Pages source to **GitHub Actions** and
   replace the publish step with `actions/deploy-pages`.
